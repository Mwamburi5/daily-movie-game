### Goal 2 — implement the minimal analytics dictionary

Preserve current `mode_start`, `mode_finish`, and successful `share` behavior.
Add these events with exact action-boundary calls, not broad effects:

| event | exact trigger | allowed properties | dedupe |
|---|---|---|---|
| `first_action` | first attempted gameplay action after each round start, whether valid or invalid | `mode`, `kind` or `difficulty`, fixed `action` enum | in memory once per round |
| `help_open` | every explicit overview or mode Help open | `mode` or `overview`, `state=menu\|playing\|result` | once per explicit open |
| `help_return` | first gameplay action after Help closes in the same mounted round | `mode`, `resolved=true\|false` based on whether that action advances valid state | arm on close, consume once |
| `friction` | an actual invalid/misfire/one-away/miss/no-play-draw state transition | `mode`, fixed `kind`, bounded `count_bucket` | once per resulting transition |
| `share_attempt` | copy/share button promise resolves | `mode`, `result=copied\|manual_fallback` | once per click resolution |
| `replay` | explicit replay/deal-again action | `mode`, `kind` or `difficulty` | once per click |
| `mode_start` extension | entry to a mode from the menu | `session_mode_ordinal=1\|2\|3\|4+` | page-memory counter; replay retains the current ordinal |

Keep existing successful `share` for backwards-compatible counts; a successful
copy can emit both one `share_attempt(result=copied)` and one existing `share`.
A manual fallback emits `share_attempt(result=manual_fallback)` and no successful
`share`.

Define mode-specific action/friction enums centrally or beside the analytics
contract so call sites cannot send arbitrary strings. Use no timestamps or IDs
as app-supplied properties. Analytics failures must remain unable to interrupt
gameplay.
